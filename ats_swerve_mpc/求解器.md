# SE(2) iLQR-MPC 求解原理与当前配置

> 2026-11-20 文档同步。本文保留求解推导；参数、模块任务与最终测试分别以[包README](README.md)、[主报告第5节](../../../docs/调研/无先验地图钻洞高速导航优化调研报告.md)和[2027最终方案](../../../docs/nav_acceptance/20261116_2027_final_test_plan.md)为准。当前源码已将 SE(2) 离散动力学升级为精确指数映射积分，并将实时控制步长（`control_rate_hz: 50.0`，按实测时钟 `step_dt` 动态计算首步执行器约束与 warm-start 前移）与预测时域离散步长（`dt: 0.05 s`，`horizon: 60`）解耦。

这份文档描述的对象不是一个孤立的 MPC 求解器，而是 ATS 四驱四转舵轮导航链中的完整“规控设计”。JPS 负责离散全局拓扑搜索，MINCO S3 和独立 yaw 负责把拓扑路线变成连续、时间化、可检查的轨迹，footprint safety 与 Local Collision Repair 负责候选轨迹安全，Goal Manager 负责目标身份和执行授权，`ats_swerve_mpc` 负责在授权 reference 上做 SE(2) 跟踪并输出车体系速度。MPC 只是执行跟踪层，不能替代地图融合、全局搜索、MINCO 平滑、目标授权或故障恢复。

完整主链为：

```text
Point-LIO / registered_scan
    -> ROGMap probability, inflation, 3D ESDF
    -> numerical ground projection
    -> ats_rog_map_adapter terrain/static/slope fusion
    -> immutable PlanningMapSnapshot
    -> Goal Manager goal/action, lease and identity checks
    -> JPS (GridJps, optional controlled A* fallback)
    -> MINCO S3 position trajectory + independent yaw spline
    -> clearance, oriented footprint safety, Local Collision Repair
    -> final retimed ExecutionCommand
    -> TrajectoryTracker
    -> SE(2) iLQR MPC (QP shadow is diagnostic only)
    -> four-swerve feasibility checks
    -> /cmd_vel/autonomy_raw -> arbiter -> /cmd_vel/selected
    -> twist_to_motion_ctrl -> /motion_control
    -> MuJoCo or real chassis
```

本文介绍MPC数学、代价和约束。跨模块frame、time、snapshot、QoS、ownership和失败零速契约统一见主报告；历史测试不视为当前revision通过，未实测的实时性、内存与物理接触不作为实车结论。

结论：当前 `ats_swerve_mpc` 是一个“有限时域、非线性 SE(2) 轨迹跟踪 MPC”，内部采用手写的 iLQR/Gauss-Newton 迭代求解。它不是 OSQP、IPOPT、CasADi 或标准 QP/NLP 求解器，也没有把四个舵角作为独立状态进行动力学优化。

核心实现位于 [`se2_mpc_controller.cpp`](src/se2_mpc_controller.cpp) 和 [`se2_mpc_controller.hpp`](include/ats_swerve_mpc/se2_mpc_controller.hpp)。

**2. 状态和控制变量**

源码明确采用：

```text
状态：世界坐标系 [x, y, yaw]
控制：车体坐标系 [vx, vy, wz]
```

定义位于 [`se2_mpc_controller.hpp`](include/ats_swerve_mpc/se2_mpc_controller.hpp)。

因此：

- `x、y、yaw` 表示机器人在世界系中的位姿；
- `vx、vy、wz` 表示车体系速度；
- `vy` 不会被强制为零；
- 机器人可以前进、横移、旋转，也可以同时执行三者；
- 这不是差速模型，没有 `vy=0`、ICR 或曲率约束。

最终发布到 `geometry_msgs::msg::Twist`：

```text
linear.x  = vx
linear.y  = vy
angular.z = wz
```

**3. SE(2) 离散动力学**

动力学与解析雅可比位于 [`se2_model.cpp`](src/se2_model.cpp) 和 [`se2_model.hpp`](include/ats_swerve_mpc/se2_model.hpp)（支持显式传入每步 `step_dt`，不再硬编码 50 ms）。

在单步零阶保持车体系速度 $u_k = [v_x, v_y, \omega_z]^T$ 与步长 $\Delta t$ 下，采用精确 SE(2) 指数映射积分：令 $\theta = \omega_z \Delta t$、$\bar{\psi}_k = \psi_k + \frac{1}{2}\theta$、$s(\theta/2) = \operatorname{sinc}(\theta/2) = \frac{\sin(\theta/2)}{\theta/2}$（小角区采用 4 阶泰勒展开避免 $0/0$ 奇异），则

$$
x_{k+1}
=
x_k + \Delta t \, s(\theta/2)
\left(
v_x\cos\bar{\psi}_k - v_y\sin\bar{\psi}_k
\right)
$$

$$
y_{k+1}
=
y_k + \Delta t \, s(\theta/2)
\left(
v_x\sin\bar{\psi}_k + v_y\cos\bar{\psi}_k
\right)
$$

$$
\psi_{k+1}
=
\operatorname{wrapToPi}
\left(
\psi_k + \Delta t\,\omega_z
\right)
$$

其中：

- `dt` 是预测时域内的离散步长，当前配置为 `0.05 s`，`horizon = 60`，预测时域为 `3.0 s`；
- 实时控制周期由 `control_rate_hz`（当前默认 `50.0 Hz`，约 `20 ms`）与每拍实测经过时间 `actual_step_dt` 决定，两者完全解耦：首步速度/轮速/舵角增量约束与控制序列时间前移按实测 `first_step_dt` 计算，后续预测步按 `dt` 展开；
- 角度通过 `atan2(sin(angle), cos(angle))` 归一化到 `(-pi, pi]`，避免跨 `pi` 时出现跳变。

对应解析雅可比 `A = df/dx`、`B = df/du`（含 $\partial s / \partial (\theta/2)$ 与 $\omega_z$ 到 $x,y$ 的二阶耦合项 $\frac{1}{2}\Delta t^2$）在 [`se2_model.cpp`](src/se2_model.cpp) 中计算，供 iLQR backward pass 与 LTV-QP shadow 线性化使用。

**4. 参考轨迹如何进入 MPC**

参考处理在 [`trajectory_tracker.cpp`](src/trajectory_tracker.cpp) 中完成。

收到 `/minco/reference_path` 后，节点会：

1. 读取每个 `PoseStamped` 的时间戳；
2. 如果单点时间戳为空，则使用 `fallback_path_dt` 补齐；
3. 如果时间不单调，则重新生成单调时间轴；
4. 拒绝少于两个点的轨迹；
5. 拒绝 frame 与 MPC `frame_id` 不一致的轨迹；
6. 将每个点转换为：

```text
TimedState {
  time,
  [x, y, yaw]
}
```

路径安装逻辑位于 [`ats_swerve_mpc_node.cpp`](src/ats_swerve_mpc_node.cpp)。

当前机器人位姿会投影到最近的轨迹线段，代码位于 [`trajectory_tracker.cpp`](src/trajectory_tracker.cpp)。

投影具有以下限制：

- 轨迹进度不能回退；
- 允许有限的后向搜索窗口；
- 允许有限的前向搜索窗口；
- 防止定位噪声导致投影跳回旧路径；
- 防止误投影到远处轨迹段；
- 对原地旋转段使用 yaw 误差推进；
- 对路径拐角和 yaw 跨 `pi` 的情况使用最短角度差。

横向误差越大，参考轨迹推进速度越慢：

```yaml
cross_track_slowdown_start: 0.15
cross_track_slowdown_end: 0.60
min_reference_progress_scale: 0.25
```

也就是说，机器人偏离轨迹时不会盲目追逐远处目标，而是降低 horizon 的时间推进，让 MPC 先将机器人拉回轨迹附近。

**5. MPC reference horizon 构建**

`buildHorizon()` 位于 [`trajectory_tracker.cpp`](src/trajectory_tracker.cpp)。

每一个控制周期，轨迹跟踪器会生成：

```text
horizon + 1 = 61 个参考状态
```

每个参考点包含：

```text
reference.state   = [x, y, yaw]
reference.control = [vx, vy, wz]
```

轨迹位置速度先通过相邻世界系点计算：

$$
v_{world}
=
\frac{p_{k+1}-p_k}{t_{k+1}-t_k}
$$

再根据参考 yaw 转换到车体系：

$$
v_{body}=R(\psi)^T v_{world}
$$

代码对应 [`trajectory_tracker.cpp`](src/trajectory_tracker.cpp)。

因此，当机器人 yaw 为 90 度、世界系速度沿 y 轴时，MPC 会得到正确的车体系前向或横向速度，而不是错误地把世界速度直接当成车体速度。

**6. 代价函数**

代价函数位于 [`se2_mpc_controller.cpp`](src/se2_mpc_controller.cpp)。

每个阶段的代价为：

$$
J_k=
e_{x,k}^TQe_{x,k}
+
e_{u,k}^TRe_{u,k}
+
\Delta u_k^TR_d\Delta u_k
$$

其中：

$$
e_{x,k}=x_k-x_k^{ref}
$$

yaw 误差会单独进行 `wrapToPi` 处理。

$$
e_{u,k}=u_k-u_k^{ref}
$$

$$
\Delta u_k=u_k-u_{k-1}
$$

最终总代价为：

$$
J=
\sum_{k=0}^{N-1}J_k
+
e_{x,N}^TQ_Te_{x,N}
$$

当前配置为：

```yaml
state_weight:        [18.0, 18.0, 10.0]
terminal_weight:     [28.0, 28.0, 8.0]
control_weight:      [0.12, 0.12, 0.08]
control_delta_weight: [0.70, 0.70, 0.60]
```

含义是：

- x/y 位置误差权重较高；
- yaw 误差权重相对较低；
- 控制量变化被惩罚，降低舵轮速度和车体速度突变；
- 终端误差权重更高，推动预测末端靠近参考轨迹。

**7. Warm Start**

warm start 逻辑位于 [`se2_mpc_controller.cpp`](src/se2_mpc_controller.cpp)。

第一次求解：

```text
初始控制序列 = reference.control
```

后续周期：

1. 将上一周期控制序列左移一格；
2. 当前 reference control 与上一周期 warm control 混合：

```text
0.7 * warm_control + 0.3 * reference_control
```

3. 对每个控制步重新执行约束裁剪；
4. 求解完成后保存新的控制序列；
5. 只发布第一个控制量；
6. 下一个周期重新预测和优化。

急停、定位异常、轨迹失效、求解失败时调用 `reset()`，清空 warm start，避免旧控制序列重新驱动车辆。

唯一的例外是同一 goal、同一定位 epoch、同一 planner generation 内的换轨（`onExecutionCommand` 的
`same_goal_epoch_generation`，且未处于 fail-stop）：`installPath(..., keep_control_state=true)` 不调用
`reset()`，也不清零 `last_control_`，下一拍照常左移 warm start。否则 `max_a * dt` 增量限幅会把换轨第一拍
压到约 0.1 m/s。generation、epoch、goal 变化，首次安装与所有停车路径仍然清零。

求解用的初始 yaw 做了旋转相位补偿：`psi + omega * t_d / 2`（`rotationPhaseCompensatedState`），omega 取上一拍已发布指令的 wz，
t_d 取 `command_latency_compensation`；位置、投影与终点判定仍用未补偿的里程计状态。

**8. iLQR backward pass**

反向递推位于 [`se2_mpc_controller.cpp`](src/se2_mpc_controller.cpp)。

终端初始化：

$$
V_x=2Q_Te_N
$$

$$
V_{xx}=2Q_T
$$

然后从 $N-1$ 反向递推到 0，计算局部二次模型：

```text
Q_x
Q_u
Q_xx
Q_ux
Q_uu
```

`Q_uu` 会加入正则化：

$$
Q_{uu}
\leftarrow
Q_{uu}+\lambda I
$$

当前：

```yaml
regularization: 1.0e-5
```

使用 Eigen `LDLT` 分解求解前馈和反馈增益：

$$
k_k=-Q_{uu}^{-1}Q_u
$$

$$
K_k=-Q_{uu}^{-1}Q_{ux}
$$

如果：

- `LDLT` 分解失败；
- 增益包含 `NaN/Inf`；
- 参考长度不足；

则本周期求解失败，不会把旧 warm start 冒充成新的闭环解。

**9. Forward pass 和线搜索**

主求解器位于 [`se2_mpc_controller.cpp`](src/se2_mpc_controller.cpp)。

候选控制为：

$$
u_k^{candidate}
=
u_k+
\alpha k_k+
K_k(x_k^{candidate}-x_k)
$$

其中：

```yaml
max_iterations: 6
line_search_decay: 0.5
min_line_search_step: 0.05
convergence_tolerance: 1.0e-3
```

线搜索过程：

```text
alpha = 1.0
如果代价没有下降，则 alpha *= 0.5
直到 alpha < 0.05
```

只有满足：

```text
candidate_cost + 1e-9 < current_cost
```

才接受候选控制。

这里有一个重要语义：

- 反向递推成功，说明本周期至少获得了数值可信的反馈增益；
- 线搜索没有接受候选，不一定代表失败；
- 如果当前 warm start 已经是约束可行驻点，候选可能被约束裁剪回原序列；
- 只有 backward pass 奇异、代价非有限或序列长度错误，才判定求解失败。

**10. 四舵轮约束实现**

四个轮心位置由：

```text
(+wheel_base_x, +wheel_base_y)
(+wheel_base_x, -wheel_base_y)
(-wheel_base_x, +wheel_base_y)
(-wheel_base_x, -wheel_base_y)
```

定义。

每个轮子的车体系速度为：

$$
v_{i,x}=v_x-\omega_z y_i
$$

$$
v_{i,y}=v_y+\omega_z x_i
$$

实现位于 [`se2_mpc_controller.cpp`](src/se2_mpc_controller.cpp)。

约束分三层：

1. 车体速度限幅：

$$
|v_x|\le v_{x,max},\quad
|v_y|\le v_{y,max},\quad
|\omega_z|\le \omega_{z,max}
$$

2. 单轮速度限幅：

$$
\max_i\|v_i\|\le v_{wheel,max}
$$

如果超过上限，代码对整个 `[vx, vy, wz]` 做等比例缩放，保持同一个车体 Twist，不单独修改某个轮子。

3. 车体加速度限幅：

$$
|\Delta v_x|\le a_{x,max}\Delta t
$$

$$
|\Delta v_y|\le a_{y,max}\Delta t
$$

$$
|\Delta\omega_z|\le a_{\omega z,max}\Delta t
$$

舵轮模块增量约束位于 [`se2_mpc_controller.cpp`](src/se2_mpc_controller.cpp)。

单轮速度变化不能超过：

$$
\|v_i^k-v_i^{k-1}\|
\le
a_{wheel,max}\Delta t
$$

舵角变化通过两个连续轮速向量的真实夹角计算：

$$
\Delta\theta_i=
\arccos
\left(
\frac{v_i^k\cdot v_i^{k-1}}
{\|v_i^k\|\|v_i^{k-1}\|}
\right)
$$

代码没有对点积取绝对值，因此 180 度反向会被正确识别为舵角大变化。

如果候选控制不可行，则在：

```text
previous -> limited
```

的线段上执行 40 次二分搜索，找到最大可行比例。实现位于 [`se2_mpc_controller.cpp`](src/se2_mpc_controller.cpp)。

这是一种“候选控制投影/回退”策略，不是将约束直接纳入完整的 constrained iLQR 或 QP。

**11. ROS 控制循环和安全门**

控制循环位于 [`ats_swerve_mpc_node.cpp`](src/ats_swerve_mpc_node.cpp)，实时运行默认配置为 `50 Hz`（周期 `20 ms`，由 `control_rate_hz` 参数控制，并与预测步长 `dt = 0.05 s` 解耦；每拍首步增量约束按实测 `actual_step_dt` 计算）。

每周期顺序为：

1. 检查 localization 是否为 `TRACKING`；
2. 检查 `ExecutionCommand` 租约；
3. 检查云台状态和 TF 健康；
4. 检查里程计是否新鲜；
5. 检查轨迹是否存在；
6. 将当前位姿投影到轨迹；
7. 构建 reference horizon；
8. 检查目标误差和轨迹 deadline；
9. 调用 `Se2MpcController::solve()`；
10. 成功后发布第一步 `[vx, vy, wz]`；
11. 发布预测路径和 reference horizon 调试路径。

当前 RViz 调试输出为：

```text
/ats_swerve_mpc/predicted_path
/ats_swerve_mpc/reference_horizon
```

失败路径统一调用 [`ats_swerve_mpc_node.cpp`](src/ats_swerve_mpc_node.cpp)：

- 清零 `last_control_`；
- 发布零速度；
- `controller_->reset()`；
- 下一控制周期继续发布零速度。

急停函数位于 [`ats_swerve_mpc_node.cpp`](src/ats_swerve_mpc_node.cpp)，会：

- 清空轨迹；
- 清空轨迹 deadline；
- 记录最新 stop 时间；
- 清空 MPC warm start；
- 发布零速度。

`ExecutionCommand` 还会校验 manager incarnation、command sequence、goal ID、localization epoch、map generation、gimbal request sequence 等字段，防止急停后的旧轨迹恢复运动。

**重要限制**

当前 MPC 预测模型只包含底盘中心的 SE(2) 运动学。四个舵轮只参与轮速、轮加速度和舵角速率约束，并未作为 MPC 状态。因此当前没有显式建模：

- 舵角状态和舵角执行器延迟；
- 轮胎侧偏、摩擦、接触力；
- 电机电流、扭矩和转速动态；
- 轮胎打滑；
- 地图碰撞、footprint clearance 或障碍物代价；
- 实车底盘通信延迟的完整闭环模型。

因此，准确表述应该是：

> 当前实现是“带四舵轮可行性约束的 SE(2) iLQR-MPC 轨迹跟踪器”，而不是完整四舵轮动力学 MPC。

另外，源码中虽然记录了 `solve_time_ms` 并在超过控制周期比例时告警，但 50 Hz、约 6 ms、内存占用等性能指标仍必须在目标实车或目标计算机上实测，不能从当前代码结构直接推导。
